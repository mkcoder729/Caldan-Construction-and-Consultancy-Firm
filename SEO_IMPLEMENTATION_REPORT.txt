9. PRODUCTION SETTINGS — REQUIRED ENV VARS (verify on Railway)
================================================================================
The following environment variables MUST be set in Railway for the site to
serve correctly under https://caldanconstruction.com/:

  ALLOWED_HOSTS              = caldanconstruction.com,www.caldanconstruction.com
                                (comma-separated; localhost and 127.0.0.1 already default)
  SITE_URL                   = https://caldanconstruction.com
  BASE_URL                   = https://caldanconstruction.com
  SECURE_SSL_REDIRECT        = True
  SECURE_HSTS_SECONDS        = 31536000
  SECURE_HSTS_INCLUDE_SUBDOMAINS = True
  SECURE_HSTS_PRELOAD        = True
  CSRF_COOKIE_SECURE         = True
  SESSION_COOKIE_SECURE      = True
  DEBUG                      = False

Without these, http://caldanconstruction.com will serve a 200 OK duplicate of
https://caldanconstruction.com — Google will index both as separate URLs.

12. REMAINING ITEMS (POST-DEPLOY, RAILWAY-SIDE)
================================================================================
These are env-var / server-config changes that only you can make on Railway:

  1. Confirm ALLOWED_HOSTS env var includes caldanconstruction.com and
     www.caldanconstruction.com. (See section 9.)
  2. Set SITE_URL=https://caldanconstruction.com so robots.txt Sitemap
     directive uses the production URL even if request.get_host() is empty.
  3. Enable SECURE_SSL_REDIRECT, HSTS, and SECURE cookies. (See section 9.)
  4. Submit https://caldanconstruction.com/sitemap.xml in Google Search
     Console (URL Inspection → Sitemaps → Add).
  5. In Google Search Console, use URL Inspection on the homepage and
     request indexing. Repeat for the 8 marketing landing pages.
  6. Verify canonical + OG render in "View Page Source" of the live site
     (Googlebot will see exactly what you see).
  7. Confirm the sameAs URLs in Organization JSON-LD are the real
     Facebook/LinkedIn/Instagram profile URLs (currently placeholders).
  8. Replace the placeholder social links in footer with real URLs.

13. SITELINKS — REALISTIC EXPECTATIONS
================================================================================
Google sitelinks for branded queries (e.g., "Caldan Construction") are
algorithmically generated and CANNOT be manually forced. What we have
done puts the site in the strongest possible technical position:

  ✓ Clean, unique <title> and <meta description> on every public page.
  ✓ Self-referencing canonical URLs on every indexable page.
  ✓ Organization schema with brand name "Caldan Construction" + sameAs.
  ✓ WebSite schema with @id, publisher reference, inLanguage en-KE.
  ✓ Clear internal linking from the header nav and footer.
  ✓ Sitemap with all detail URLs and lastmod timestamps.
  ✓ robots.txt blocking all internal/private paths.
  ✓ No duplicate titles, no duplicate meta, no duplicate OG.
  ✓ FAQPage schema on /services/ (FAQ rich-result eligible).
  ✓ ItemList schema on /services/ (service provider rich results).
  ✓ Consistent favicon and theme-color across all pages.
  ✓ HTTPS-ready (after Railway env vars are set).

Sitelinks typically appear when:
  1. The brand is searched by name (we have Organization + WebSite schema
     with the brand as primary name).
  2. Multiple distinct top-level pages exist with clear titles (we now have
     unique titles on 8+ landing pages + 9 service pages + N project pages).
  3. Internal linking makes top pages discoverable from the homepage
     (header nav has 9 entries + footer has 4 columns of links).
  4. The site has been live and indexed for some time — sitelinks usually
     appear weeks after a search-console submission, not immediately.

Once you push this code and submit the sitemap in Google Search Console,
expect 1–4 weeks for full re-crawl and potential sitelink generation.
