EXECUTIVE SUMMARY
================================================================================
Google CAN currently crawl the main marketing surface and a sitemap is served.
However, the implementation has several BLOCKERS and GAPS that will hurt
indexing and sitelink generation:

  CRITICAL (likely suppressing sitelinks / indexing)
    [C1]  base.html hard-codes "og:url" and Twitter title/description as the
          BRAND strings for EVERY page — Google sees the same title/desc/URL
          on every page even though `{% block title %}` overrides the <title>.
    [C2]  base.html has NO <link rel="canonical"> block. Only services.html
          sets one manually. Every other page is vulnerable to duplicate-
          content signals (especially with /?page= pagination & filter URLs).
    [C3]  base.html emits two <script type="application/ld+json"> blocks on
          EVERY page (WebSite + Organization). Organization schema is correct,
          but it's emitted on noindex pages too (404/500).
    [C4]  /robots.txt declares Sitemap with the SITE_URL — but only ONE Sitemap
          is registered (WebsiteSitemap). The blog index, projects index,
          compassion index, and shop index are NOT in the sitemap (they're
          listed only because WebsiteSitemap references website:blog,
          website:projects, and compassion:index). Service detail, project
          detail, blog post detail, and story detail pages are EXCLUDED —
          these are the long-tail URLs sitelinks and rich results feed on.
    [C5]  Sitemap.xml file at /templates/sitemap.xml exists (untracked) but is
          unused; only the dynamic Django sitemap view is wired. Verify it's
          not served as a static override.

  HIGH (sitelink-eligibility problems)
    [H1]  No site_name field on the homepage <title>. Google sitelinks for
          branded searches work best when the homepage title is
          "<brand> — <tagline>" or just "<brand>". Current title is fine but
          the og:title duplication makes it harder to disambiguate.
    [H2]  No breadcrumbs anywhere on public pages. BreadcrumbList schema on
          detail pages (services, projects, blog, compassion stories) is
          strongly correlated with sitelink depth.
    [H3]  No <link rel="alternate" hreflang="..."> for en-ke (lang is hard-coded
          "en" but content is Kenyan). Not a blocker but worth noting.
    [H4]  Multiple <h1> elements on the homepage (hero h1 + partial h1s)
          because partials (_hero, _cta, _stats_bar, _compassion_strip) inject
          additional h1s. This weakens the page's topical focus signal.
    [H5]  No <meta name="theme-color"> on individual pages (only webmanifest
          sets it). Mobile Chrome uses theme-color in some SERP contexts.

  MEDIUM (polish / indexing hygiene)
    [M1]  og:image is static `{% static 'images/og-image.png' %}` — that's a
          RELATIVE path until WhiteNoise processes it. Google expects an
          absolute URL. The same applies to the Twitter card image.
    [M2]  meta description block override pattern only works because blocks
          are appended AFTER the base's `{% block meta_description %}`. The
          base block outputs a `<meta name="description">` line PLUS a
          comment-style opening. When child templates override the block,
          the base description is REPLACED — fine — but child blocks also
          re-emit og:title / og:description, so og: properties appear
          TWICE on most pages (once from base, once from child).
    [M3]  Pagination on /blog/ and /projects/ lacks `rel="prev"` /
          `rel="next"` head tags.
    [M4]  robots.txt blocks /accounts/, /admin/, /dashboard/, /api/, /setup/,
          /media/private/ — good. But /admin-projects/ and /admin-services/
          are NOT blocked (legacy aliases live at /dashboard/shop/... but the
          new admin paths are public-discoverable). Also /blog/dashboard/ is
          a real page now (line 15 blog/urls.py) and is NOT disallowed.
    [M5]  /media/private/ is blocked but the actual MediaCloudinaryStorage
          URL is `https://res.cloudinary.com/<cloud>/...` — robots.txt can't
          disallow a third-party CDN. Private media relies on view-level auth.

  LOW (cosmetic / future-proofing)
    [L1]  base.html `{% block robots %}` is defined but EMPTY. Pages that
          should be indexable don't emit a positive robots directive.
    [L2]  Sitemap's `lastmod` always returns None — Google will crawl less
          efficiently. Use post.updated_at / project.updated_at for dynamic
          items.
    [L3]  /templates/preloader.html is included from base.html — verify it
          doesn't include a noindex meta (it doesn't, but worth confirming).
    [L4]  Favicon cache-buster `?v=20260810` is good. But site.webmanifest
          references files that DON'T exist:
              /static/images/web-app-manifest-192x192-v2.png  — MISSING
              /static/images/web-app-manifest-512x512-v2.png  — MISSING
          Found in static/images/: apple-touch-icon-v2.png, favicon-96x96-v2.png,
          favicon-v2.ico, favicon-v2.png, favicon-v2.svg, logo.png, logo_dark.png,
          logo_light.png, og-image.png, site.webmanifest.
          Missing: web-app-manifest-192x192-v2.png, web-app-manifest-512x512-v2.png.

   • /blog/<slug>/      (every blog post — fresh content for "Caldan Construction

                       are linked from the footer of every page; Google
                       expects them in the sitemap)

The docstring claims "Aggregate listing pages handle crawl discovery for
those" — but Google does NOT guarantee crawl of all detail pages just because
the index is in the sitemap, especially if internal linking is sparse.

Also: WebsiteSitemap.lastmod() returns None for every item. This signals
"never updated" and Google may crawl less frequently. For dynamic content
(posts, projects) the function should return post.updated_at / project.updated_at.
